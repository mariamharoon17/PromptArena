About this project

A research tool for comparing AI assistants

A research-driven tool built to objectively compare AI coding assistants so developers and researchers can make informed decisions.

Project Overview

AI-assisted coding is transforming how software is built, but how does one tool compare to another?

PromptArena is a web-based benchmarking platform developed as part of an MSc dissertation at Aston University. It provides a systematic, repeatable framework for comparing the performance of three leading AI language models: ChatGPT (OpenAI), Claude (Anthropic) and Gemini (Google) across a range of software development tasks.

The tool addresses a significant gap in existing research: while individual AI tools are widely discussed, rigorous side-by-side comparisons using standardised tasks and objective metrics are rare. PromptArena fills this gap by providing a reusable, extensible evaluation framework.

Methodology

How benchmarking works

Step 01
Prompt Design
Standardised prompts are designed across 7 task categories to ensure fair, repeatable testing.
Step 02
Simultaneous Querying
Each prompt is sent to all 3 AI models simultaneously via their official APIs, ensuring identical conditions.
Step 03
Dual Scoring
Each response is scored two independent ways: a transparent rule-based engine and an LLM-as-Judge across four weighted quality dimensions.
Step 04
Storage & Analysis
Results are saved to a database (SQLite locally, Azure MySQL in the cloud) and can be exported as CSV or PDF for further analysis.

Each benchmark run measures Response Time (ms) and Token Usage, and scores four quality dimensions: Substance, Completeness, Clarity and Reliability combined into an Overall Score out of 100 for each model, produced both by a rule-based engine and by an LLM-as-Judge.

Two Scoring Methods

Rule-based and LLM-as-Judge, side by side

Every answer is scored twice, using the same four dimensions and the same weights (Substance 35%, Completeness 20%, Clarity 25%, Reliability 20%). Keeping both lets the two methods be compared directly against human judgement, a core part of the research.

Rule-based engine
A fixed set of rules inspects each response for structure, length and content signals. Fully transparent and reproducible the same answer always gives the same score but, it measures presentation, not correctness.
LLM-as-Judge
A fixed judge model reads each answer and rates the same four dimensions, applied equally to all three models at temperature 0. Because it reads the content, it can reward genuine correctness, not just structure.

Both are automated estimates of quality. Human review, gathered through a participant survey, remains the final point of comparison.

Working Modes

Three ways to use the same framework

The platform began as a single benchmark form. It now covers two further modes that put the same three models to work on real development tasks, scored identically so the results remain comparable across the whole dataset.

Benchmark
One prompt across seven task categories, sent to all three models at once and scored twice.
Build a Website
Each model returns a complete file for the same brief. The output is rendered in a sandboxed preview and checked for rendering, responsiveness, semantic landmarks and labelled form inputs, then scored on the standard four dimensions.
Code Assist
Real code with a chosen task: explain, find the bug, write tests, refactor or security review. All three answers are returned side by side with response time, rule score and judge score.

All three modes write to the same table, so every run counts towards the study sample and exports together.
